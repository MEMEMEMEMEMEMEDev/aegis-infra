# base-images/consumers.txt — the repositories that stand on a base
# aegis OWNS. One repository URL per line, in either of the two forms
# GitHub answers to (the job normalises both to https):
#
#   git@github.com:<owner>/<repo>.git
#   https://github.com/<owner>/<repo>(.git)
#
# The list is EVERY repository that builds an image, whatever base it
# stands on: with more than one member (nginx for the static fronts,
# node for the backends) each repository matches ONE of them. After a
# successful build of a member, the base-images job clones every
# repository listed here and greps it for a `Containerfile` whose FROM
# names `aegis-base-<member>@sha256:…` (with or without a tag before
# the `@`). Where it finds one, it rewrites THAT line to the new
# `<tag>@<digest>` and commits it to the default branch — which is what
# makes the consumer's own pipeline rebuild on the patched base. A
# repository in which no Containerfile names that member is SKIPPED
# with a notice: it is not a consumer of that base, a fact and not a
# failure (an event records it; no propagation metric is written for
# the pair). What DOES leave the run UNSTABLE, with a metric and an
# event naming the repo, is a clone that fails, a push that fails, or
# a diff the guard refuses. Nothing else in a repository is ever
# written.
#
# The block below is DERIVED from orgs/*.yaml — the `repo` of every
# service that declares an image — by `aegis org apply`, and it is
# re-derived WHOLE on every run: whatever is edited between the markers
# does not survive the next one.
# --- DERIVED by aegis-org (base consumers): do not edit by hand ---
# --- END DERIVED ---
