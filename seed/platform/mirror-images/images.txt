# mirror-images — imágenes de TERCEROS que la plataforma espeja al
# registry interno y firma con la llave de aegis.
#
# POR QUÉ EXISTE ESTE ARCHIVO
# La ClusterPolicy require-aegis-signature exige firma propia para todo
# Pod de un namespace de tenant (imageReferences '*'). Una imagen
# pública NO puede correr ahí: no está firmada con nuestra llave y no
# vamos a debilitar la política por comodidad. La salida correcta es
# traerla, ESCANEARLA y firmarla nosotros — que es exactamente lo que
# hace el job mirror-images. El resultado es que todo lo que corre en un
# tenant pasó por el mismo control, sea código nuestro o de terceros.
#
# FORMATO
#   <origen>@<digest>   <destino>:<tag>
#
# El origen se pinnea POR DIGEST, no por tag. Un tag es un puntero
# mutable: quien controla el registry de origen puede reapuntarlo a otro
# contenido sin que nos enteremos. El digest es el contenido. El tag se
# deja en el comentario para que un humano sepa qué está leyendo.
#
# CÓMO ACTUALIZAR UNA IMAGEN
#   1. crane digest <origen>:<tag-nuevo>
#   2. editar la línea acá (digest Y tag del destino)
#   3. commit + push  →  correr el job mirror-images
#   4. bumpear la referencia en el manifiesto que la consume
# El paso 4 es aparte a propósito: espejar no despliega. Traer una
# imagen nueva y ponerla en producción son dos decisiones distintas.
#
# Líneas vacías y las que empiezan con # se ignoran.

# nginx-unprivileged 1.31.3-alpine — base de los TRES fronts estáticos:
# portafolio, blog y ejemplo.
#
# POR QUÉ LA VARIANTE unprivileged Y NO nginx A SECAS. Dos razones, y las
# dos son obligatorias en esta plataforma:
#
#   1. Escucha en 8080. La NetworkPolicy de un inquilino sólo permite
#      entrada del borde al 8080; con el nginx normal (puerto 80) el pod
#      arranca bien y NO recibe tráfico nunca. Es la peor clase de fallo:
#      silencioso.
#   2. Corre como UID 101, no root. Los namespaces de inquilino están en
#      Pod Security Standards `restricted`: un contenedor que pida root
#      es RECHAZADO en admisión y el pod no llega a existir.
#
# POR QUÉ SE ESPEJA RECIÉN AHORA, que es lo que de verdad hay que contar.
#
# No estaba acá. Los tres fronts la traían de Docker Hub EN CADA BUILD.
# Se descubrió el 2026-08-09 porque la build 38 del portafolio murió así:
#
#   Retrieving image nginxinc/nginx-unprivileged from index.docker.io
#   error building image: Get "https://index.docker.io/v2/": ...
#
# Y el fallo del build es la consecuencia menor. La mayor es que
# firmábamos con cosign el artefacto RESULTANTE mientras la base sobre la
# que se construyó no la había verificado nadie, y encima por TAG. La
# política de firma hacía exactamente lo que promete —verificar lo que
# nosotros firmamos— y aun así había terreno sin verificar debajo. Es
# justo el agujero que este archivo existe para cerrar.
#
# El digest de origen es el MISMO en public.ecr.aws que en Docker Hub;
# se midió con `crane digest` contra los dos antes de elegir. Así que
# usar ECR no cuesta nada y esquiva los límites de tasa del Hub.
